      Combinar promesas

      await Promise.all([a, b]);        // todas, o falla con la primera que rechace

await Promise.race([a, b]);       // la primera que se asiente
await Promise.any([a, b]);        // la primera que se cumpla

      Event loop en una línea

      // 1. código sincrónico (incluye executor de Promise y async hasta el await)
// 2. todas las microtareas (then, catch, finally, await)
// 3. una macrotarea (setTimeout, eventos) y vuelta al 2

      JavaScript tiene un solo hilo: lo asincrónico no corre "en paralelo", se encola y espera su turno.

      Asincronía

      ¿Qué es una promesa?

      Un objeto que representa un valor que todavía no está: el resultado de una operación asincrónica. Tiene tres estados: pendiente, cumplida (fulfilled) o rechazada (rejected). Una vez que se asienta, no cambia más. Con .then recibo el valor, con .catch el error y .finally corre siempre.

      ¿Por qué existen las promesas si ya había callbacks?

      Con callbacks, cada paso asincrónico anidaba otro nivel (el "callback hell") y el manejo de errores se repetía en cada uno. Las promesas se encadenan de forma plana, un solo .catch atrapa errores de toda la cadena, y se pueden combinar con Promise.all.

      ¿Qué hacen async y await?

      async hace que una función siempre devuelva una promesa. await pausa esa función hasta que la promesa se asienta y devuelve su valor; si se rechaza, tira el error en esa línea y lo atrapo con try/catch. Es azúcar sintáctica sobre promesas: se lee como código sincrónico.

      ¿await bloquea el programa?

      No. Pausa solamente la función async donde está. El resto del programa sigue: el event loop atiende otros eventos, timers y respuestas mientras tanto. Por eso la interfaz no se congela.

      ¿Qué es el event loop?

      JavaScript corre en un solo hilo con una pila de llamadas. Las operaciones asincrónicas (timers, red, eventos) las resuelve el entorno (navegador o Node) y, cuando terminan, encolan su callback. El event loop espera a que la pila esté vacía, vacía la cola de microtareas y después toma una macrotarea, en ciclo.

      ¿Microtareas contra macrotareas?

      Microtareas: .then, .catch, .finally, lo que sigue a un await y queueMicrotask. Macrotareas: setTimeout, setInterval, eventos del DOM, I/O. Después de cada macrotarea se vacían todas las microtareas; por eso una promesa resuelta siempre sale antes que un setTimeout(fn, 0).

      ¿Promise.all, allSettled, race o any?

      all: espera todas y falla con la primera que rechace. allSettled: espera todas y te da el estado de cada una, sin fallar. race: se queda con la primera que se asiente, bien o mal (sirve para timeouts). any: la primera que se cumpla; falla solo si fallan todas.

      ¿Cómo hacés pedidos en paralelo y cuándo en serie?

      En paralelo: await Promise.all(ids.map(id => api.get(id))), tarda lo que el más lento. En serie: for...of con await adentro, solo cuando un pedido depende del resultado del anterior. forEach con una función async no espera a nadie.

      ¿Por qué fetch no falla con un 404 o un 500?

      Porque para fetch el pedido salió bien: hubo respuesta. Solo rechaza por errores de red (sin conexión, DNS, CORS). Hay que revisar res.ok (status 200 a 299) y tirar el error a mano: if (!res.ok) throw new Error('HTTP ' + res.status).

      Lenguaje

      ¿var, let o const?

      const por defecto, let si la variable se reasigna, var nunca. var tiene scope de función y se "eleva" (hoisting) con valor undefined. let y const tienen scope de bloque y, antes de su declaración, están en la "zona muerta temporal": usarlas tira ReferenceError.

      ¿Arrow function contra function?

      La arrow es más corta, tiene return implícito y, sobre todo, no tiene this propio: usa el del lugar donde se escribió. Tampoco tiene arguments ni se puede usar con new. Para métodos de objeto que usan this, conviene la sintaxis de método o function.

      ¿Qué es un closure?

      Una función que recuerda las variables del scope donde se creó, aunque ese scope ya haya terminado. Sirve para datos privados (un contador que nadie puede tocar desde afuera) y es la base de cómo los hooks de React recuerdan valores entre renders.

  return () => ++cuenta;

      ¿== contra ===?

      === compara valor y tipo, sin conversiones. == convierte tipos antes de comparar ('1' == 1 es true). Uso siempre ===; la única excepción aceptada es x == null para cubrir null y undefined juntos.

      ¿null contra undefined?

      undefined: algo que no se asignó (variable sin valor, propiedad que no existe, función sin return). null: "vacío" puesto a propósito por el programador. ?? y ?. tratan a los dos igual.

      ¿map contra forEach?

      map devuelve un array nuevo con cada elemento transformado. forEach no devuelve nada; es para efectos (loguear, guardar). Si no vas a usar el array resultante, forEach; si sí, map. En React se usa map para renderizar listas.

      ¿Copia superficial contra copia profunda?

      { ...obj } y [...arr] copian solo el primer nivel: los objetos anidados siguen siendo compartidos. Para una copia profunda: structuredClone(obj). Es clave en React: el estado no se muta, se reemplaza por una copia nueva.

      ¿Qué es JSON y cómo se usa?

      Un formato de texto para intercambiar datos, basado en la sintaxis de objetos de JavaScript pero más estricto: claves con comillas dobles, sin funciones, sin undefined, sin comas finales. JSON.stringify(obj) pasa de objeto a texto y JSON.parse(texto) de texto a objeto.

      ¿Qué trajo ES6 (ES2015)?

      let/const, arrow functions, template literals, destructuring, parámetros por defecto, rest/spread, clases, módulos (import/export), promesas, Map/Set. Después llegaron async/await (ES2017), ?. y ?? (ES2020).
